SWAAG · OPEN-SOURCE AI AGENT FRAMEWORK

One assistant to speak to. Workers that keep moving.

SWAAG is a self-hosted orchestration framework. One manager stays responsive while background agents perform longer tasks; you can inspect their progress, questions, decisions and history, change priorities, or assign more work. Authorized autonomous continuation is configurable and disabled by default.

THE BUYER'S SITUATION

One conversation with the manager. Work across many agents.

Multiple projects need investigation, testing, automation and follow-up. Some work is independent, some depends on earlier results. You want to remain available to direct the team, not manage a separate conversation for every worker.

01 / YOUR CONTROL

One place to ask and redirect.

Request status, alter worker priorities or stop a task without manually monitoring every agent window.

02 / THE ORCHESTRATOR

Plan parallel and dependent jobs.

Workers have explicit state and tool scopes; model scheduling and resource admission avoid treating shared compute as unlimited.

03 / DURABLE HISTORY

Continue beyond a model context window.

Original messages, tool calls, results and worker events remain recoverable; relevant notes and source-backed projections are selected per task.

These are engineering scenarios, not verified paid customer examples. No measured time savings or superior reliability is claimed.

Codex, Claude Code and Dots already use workers. What is SWAAG for?

Use an existing coding agent or hosted assistant if its workflow meets your needs. SWAAG is meant for developers who want to own and adapt the agent manager itself—not merely use an agent to complete a coding task.

WHAT EXISTS IN THE SOURCE

Source-backed capabilities, explained by what they enable.

Persistent manager for the user

One canonical conversation entry point coordinates background workers and current state.

Benefit: stay informed and intervene without managing every worker directly.

Parallel workers and scheduling

Worker lifecycle, dependency plans, inference admission and liveness supervision coordinate work across available model resources.

Benefit: independent jobs can progress concurrently when capacity permits.

Complete source history and task-specific context

Raw events persist while per-call model context selectively includes relevant history, notes and recoverable summaries.

Benefit: longer work retains evidence and context without overflowing the model.

Authorized autonomous continuation

Durable wakeups, a user-authorized task backlog and optional autonomous work mode can extend tasks beyond an interactive turn.

Benefit: continue appropriate work when authorized; automatic idle dispatch is off by default.

Other agent frameworks also support orchestration, persistence and tracing. This feature list describes SWAAG's design and implementation; it is not a claim of uniqueness, safety certification or superiority over alternatives.

BEFORE USING IT

Questions a technical buyer should ask.

Is SWAAG a ready-made autonomous business assistant?

No. It is an evolving developer framework. A usable solution requires a compatible model, tool configuration, permission design, integration and appropriate testing.

Does SWAAG require a cloud-hosted AI model?

No. Local llama.cpp inference is a supported approach, and compatible external backends can also be configured. The security and suitability of a deployment depend on the actual environment.

Is the public source code free to use commercially?

Yes, under the repository's MIT license and its conditions. SWAAG's already-public source is not being offered as exclusive technology for sale.

Can SWAAG replace LangGraph, Temporal or another framework?

There is overlap in orchestration and persistence. A decision should be based on the required integrations, workflow semantics, operational constraints and direct tests. No independent comparative superiority has been established.
