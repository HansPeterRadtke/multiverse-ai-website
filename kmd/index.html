KNOWMOREDIRT / AI KNOWLEDGE RESEARCH

Ask questions about the files you already have.

Imagine a folder containing years of reports, meeting notes, logs and transcripts. You need a fact, but you don't know which document contains it. KnowMoreDiRT is research into a system that reads those files and lets you ask a question in ordinary language.

The point: find useful information without searching through every document yourself—and keep enough information about the original text to check the answer.

How someone would use it ↓See the recorded research test ↓

Research prototype. Not a ready-to-use document-search website or a proven solution for arbitrary company archives.

THE USER'S WORKFLOW

What would you actually do with it?

The intended way to use KnowMoreDiRT is straightforward. It currently exposes a small Python interface, not a finished drag-and-drop consumer application.

01 / YOUR DOCUMENTS

Choose an existing folder

Point the system to a folder of readable text. It can contain subfolders, notes, logs, transcripts, and other readable text files.

02 / YOUR QUESTION

Ask in everyday language

For example: “Who reviewed the report?” or “Which reference fixed the problem?” You do not need to construct a database query.

03 / THE RESULT

Receive a short answer

The public API returns plain text. KMD also keeps source links and evidence internally; its separate demonstration explorer shows those records for a limited test.

Today these steps are called through Python, with a local AI model available. A polished end-user interface and automatic citations in each public API response are not established features.

WHY WOULD SOMEONE WANT THIS?

Less hunting through files. More useful answers.

These are the benefits the project is designed to provide. The available small tests do not yet establish these outcomes at business scale.

USER BENEFIT

Use the folders you already have

Instead of manually converting text files into a special format, begin with existing folders of readable text.

Feature behind itRecursive raw-folder scanning and text ingestion, with no required special input schema.
USER BENEFIT

Ask instead of opening files one by one

The goal is to find a fact without guessing which filename or phrase to search for first.

Feature behind itNatural-language questions, bounded text retrieval and source-based answer generation.
USER BENEFIT

Check where information came from

A supported answer should be traceable to its original text instead of becoming an unsupported AI assertion.

Feature behind itInternal source spans, document paths and provenance records. Public answers are currently plain strings.
LONGER-TERM RESEARCH GOAL

Understand context, not just match words

Ordinary search can find a word. Many real questions depend on relationships: who did something, what “she” refers to in a later sentence, or how a status changed over time. KnowMoreDiRT is researching how to preserve that context across source text.

Current limit: broad understanding across many documents, pronouns, identity changes and time has not yet been demonstrated reliably. This is a research direction, not an already-proven user feature.

FOR TECHNICAL READERS
How the internal technology works+

Behind the simple folder-and-question workflow, the system uses local AI, a structured discourse representation, a SQLite-backed source graph, and bounded retrieval to reason about text while retaining original evidence. These are implementation details, not extra tasks for a user.

import knowmoredirt as kmd
kmd.initialize("/path/to/your/folder")
answer = kmd.question("Who reviewed the field report?")

The public interface currently returns only the answer text. The source graph and diagnostics are internal; the public research explorer is a separate demonstration, not a general citation interface.

What works today, and what is still unproven+

KnowMoreDiRT is active research. The demonstration shows limited model-backed tests with fictional documents. Accuracy across arbitrary document collections, multi-document context, and speed on new uncached questions are not yet validated.
