KNOWMOREDIRT / AI KNOWLEDGE RESEARCH

Find meaning in the chaos of your files.

Company knowledge accumulates in wildly organized folders, forgotten reports, mixed logs and files without any agreed schema. A search result is not the same as an answer: what was said, by whom, when, and in what circumstances? KnowMoreDiRT researches how to reconstruct this meaning from the raw material.

The intended benefit: find relevant information quickly by meaning, and use Discourse Representation Theory (DRT) to avoid mixing up identities, past facts, claims, quotations and imaginary events. The system is still experimental; a superiority benchmark is not established.

Research prototype. Not a ready-to-use document-search website or a proven solution for arbitrary company archives.

THE CURRENT ALTERNATIVES

Why not use Codex, Claude Code or GraphRAG?

For everyday file search or document Q&A, existing agents may be sufficient. GraphRAG and property-graph systems already combine LLM extraction, relationships and vectors. Semantic search and knowledge graphs alone are not unique.

WHAT OTHERS ALREADY DO

Search documents and build knowledge graphs.

General agents can explore files and synthesize answers. GraphRAG extracts entities, relationships and claims. These are valid existing approaches, not problems every company must replace with a new tool.

KNOWMOREDIRT'S SCIENTIFIC APPROACH

Build meaning with discourse representation.

Start with arbitrary raw folders, keep filenames and source spans, use semantic indexes for candidate retrieval, then model referents, conditions, temporal evolution and quoted or imagined contexts with DRT/DRS. The aim is to distinguish what actually follows from the sources.

This is a specialized architecture and research hypothesis, not a measured superiority claim. General accuracy, scale and cold-query speed remain unproven.

WHY DISCOURSE CONTEXT MATTERS

A document contains a law-like sentence, but another passage says it was part of a child's dream. Finding the sentence is easy; treating the dream as a real law is wrong. KnowMoreDiRT is built to keep the surrounding context and source attached to that statement, and to return unknown when real-world evidence is missing.

Illustrative hard-negative case from the original KMD recordings. Not a claim that every such case currently passes.

Scientific foundation: Discourse Representation Theory was introduced by Hans Kamp in the early 1980s, building on the wider tradition of formal linguistics and logic. Read the Stanford Encyclopedia account ↗. Using this theory in software does not automatically prove that an AI system reasons correctly.

THE USER'S WORKFLOW

Start with messy files, not a clean database.

The intended input is a folder of readable text, with arbitrary extensions, names and nested directories. The system extracts its own structure and retains exact source paths and offsets.

01 / YOUR DOCUMENTS

Point it at the existing folder

Unstructured reports, logs, transcripts and raw text. No mandatory manifest, schema or manual file naming.

02 / YOUR QUESTION

Retrieve by semantic relevance

Embeddings and lexical/referent indexes narrow down likely evidence even when the question and source use different words.

03 / THE RESULT

Interpret before answering

DRT/DSPG is intended to connect references, context and time across passages; the current public API still returns a plain answer string.

Today these steps are called through Python, with a local AI model available. A polished end-user interface and automatic citations in each public API response are not established features.

WHY WOULD SOMEONE WANT THIS?

Find the right information. Keep its meaning.

These are the benefits the project is designed to provide. The available small tests do not yet establish these outcomes at business scale.

USER BENEFIT

No large reorganization first

Start with files and folders as they exist; keep the original structure and provenance.

Feature behind itFilesystem metadata catalog and source-offset-linked text chunks.
USER BENEFIT

Find related concepts efficiently

Vector similarity can propose relevant passages without asking an LLM to compare every single database entry.

Feature behind itSemantic embeddings plus bounded search indexes; performance needs empirical comparison.
USER BENEFIT

Do not mistake a dream or old claim for a fact

Dates, referents, negation, reports and fictional scope can completely change the meaning of otherwise identical statements.

Feature behind itDRT/DRS and DSPG representation of discourse conditions, identities, temporal events and exact evidence.
LONGER-TERM RESEARCH GOAL

Understand context, not just match words

Ordinary search can find a word. Many real questions depend on relationships: who did something, what “she” refers to in a later sentence, or how a status changed over time. KnowMoreDiRT is researching how to preserve that context across source text.

Current limit: broad understanding across many documents, pronouns, identity changes and time has not yet been demonstrated reliably. This is a research direction, not an already-proven user feature.

FOR TECHNICAL READERS
How the internal technology works+

Behind the simple folder-and-question workflow, the system uses local AI, a structured discourse representation, a SQLite-backed source graph, and bounded retrieval to reason about text while retaining original evidence. These are implementation details, not extra tasks for a user.

import knowmoredirt as kmd
kmd.initialize("/path/to/your/folder")
answer = kmd.question("Who reviewed the field report?")

The public interface currently returns only the answer text. The source graph and diagnostics are internal; the public research explorer is a separate demonstration, not a general citation interface.
