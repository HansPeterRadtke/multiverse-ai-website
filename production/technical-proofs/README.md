# KMD local-model runtime verification (18 November 2026)

These files are raw, low-quality **engineering proofs**, not advertising or a customer demonstration. They are intentionally separate from the public KMD showcase and homepage.

- `kmd-wan-xavier-five-frame-proof.mp4`: actually generated by locally installed Wan2.1-T2V-1.3B on Jetson AGX Xavier. The video contains five frames, 832×480 pixels at 16 fps, and lasts approximately 0.313 seconds. Two diffusion steps. The model's GPU encoding required a dedicated `video` group session and an isolated patch that streams UMT5 blocks to the GPU instead of trying to allocate the full text encoder at once. There are no other artificial frames or interpolations. It is low quality by design and not a usable promotional film.
- `kmd-sdturbo-thor-concept.png`: actually generated by the installed SD-Turbo model on Thor (768×448 pixels, seed 20261118, three steps). It is generated conceptual artwork, not a KMD screen recording, and its fidelity is inadequate for use as a public feature image.

**Runtime findings:** Jetson AGX Xavier's remote command process did not inherit the `video` supplementary group, making ordinary CUDA initialization fail. Running the image/video worker through `sg video -c` restored CUDA. The cross-host resource broker accepted bounded Jetson allocations after a fresh host measurement. Full Wan GPU text-encoder loading exceeded available unified memory; CPU encoding was extremely slow; Accelerate's generic `cpu_offload` triggered a meta-tensor error; an isolated layer-by-layer GPU streaming implementation successfully performed both conditional/unconditional text-encoding passes and generated a five-frame video with sequential diffusion/decoder loading. An attempt with seventeen frames and six diffusion steps exceeded the safe memory reserve and was terminated without producing a video. No production code or existing GPU service was stopped or overwritten.

Thor's CUDA works through the established SSH session, but not reliably through one connected command executor's truncated supplementary-group environment. SD-Turbo completed inference once NumPy compatibility aliases were supplied to its legacy dependencies; a higher-quality SDXL + CPU offload attempt did not produce a final image, so do not claim that path is ready. Thor's resident language-model/voice services remained running. The independent GPU reservations for the tests were not to be conflated with physical VRAM and did not authorize unrelated model evictions.

Jetson's verified local isolated test files remain in `/data/var/multiverse-kmd/jetson-test/`; Thor's SD-Turbo script/output remain in `/data/var/multiverse-kmd/`. The public-facing KMD deck is separately hosted at the KMD website. Further video work should first choose a memory-bounded configuration, and should be stopped on the first low-memory safety alarm rather than sacrificing other projects.
