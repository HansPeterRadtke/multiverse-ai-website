# Multiverse: current-market differentiation and UI research — Nov 20, 2026

## Why the prior headlines were weak

"AI that can use tools" and "ask questions about files" are ordinary capabilities. Current **Codex CLI** can inspect a repository, edit, run local commands, use plugins/MCP, delegate agents, resume, and perform code review; current **Claude Code** provides tool/skill workflows, hooks, subagents and context management. Neither feature set should be implicitly called innovative simply because it involves an LLM. Read original product capabilities, not old comparisons with early chat-only assistants: https://learn.chatgpt.com/docs/cli and https://claude.com/resources/articles/steering-claude-code-skills-hooks-rules-subagents-and-more .

**SWAAG**: it is reasonable for a buyer needing coding help to choose an established coding agent. SWAAG is relevant as a *developer foundation* for tailoring a persistent agent runtime to an existing self-managed model/tool/communication infrastructure, including one orchestrator, tool boundaries, source-preserving task/history events, and controlled worker behavior. These architectural choices are inspectable on GitHub; there is no controlled performance, reliability or price superiority study. Read SWAAG source, README, manual and design principles. Do not label generic tool use, local execution, multi-agent orchestration, or persistence as proprietary features.

**KnowMoreDiRT**: Codex/Claude Code already search and interpret documents, so simply ingesting folders and answering questions is not its competitive argument. Its research problem is *context-sensitive factual interpretation*: maintain referents and identity hypotheses, distinguish assertions from allegations, track when a state was claimed/current, preserve source evidence, detect incompatible claims, and return `unknown` when adequate grounded evidence is absent. Its DRT/DSPG approach has specialized internal data structures for these. The current public API returns plain text, not bundled citations; the experimental test corpus and local-model architecture do not prove superior accuracy over agents or mature retrieval systems. Its own `docs/evaluation.md` has limitations and historical/conditional fixture scores; do not cite success rates without a dated baseline-consistent current run. Public repo: https://github.com/HansPeterRadtke/KnowMoreDiRT .

**CapOv — Captain Obvious**: real public Python package: https://pypi.org/project/capov/ ; repository https://github.com/HansPeterRadtke/capov . PyPI JSON checked Nov 20 shows v0.1.6, author Hans-Peter Radtke, MIT, Python >=3.11, latest public files uploaded 2025-06-15. An isolated install in `/data/tmp/capov-marketing-verify-20261120/venv` successfully processed a simple source file with duplicate/missing imports. However `python -m capov.tests` in that isolated environment reported 6 tests run, 5 failures. Do not claim universally safe fixes, full suite green or that it outperforms Ruff (which already offers broad safe autofixes: https://docs.astral.sh/ruff/linter/ ). PyPI Stats `https://pypistats.org/api/packages/capov/recent` returned 34 downloads in the preceding month and 12 in the preceding week as of Nov 20; these count download events, **not distinct people, installations or active use**. No numerical counts on evergreen site because they are time-sensitive and small. The meaningful site evidence is that this is a real, `pip install capov` package with public source and a working small example.

## UI and UX original sources read (private Raspi library)

Selected source material, not an exhaustive cover-to-cover reading of the library:

1. *Introduction to Human–Computer Interaction*, Hornbæk/Kristensson/Oulasvirta (Oxford University Press, 2025), 865-page original PDF, especially chapter 23 **User Interfaces** and chapter 27 **Commands and navigation**, plus content index. Chapter 23 frames UIs around interaction with actual people and tasks, not internal architecture; chapter 27 documents the vocabulary problem, meaningful command labels, information scent, and how navigation labels should match people's mental goal. Source under `/data/var/Knowledge Library/visual-perception/ux-design-psychology-and-hci-free-20261107/05-2025-open-access-hci-textbook/` on Raspi.
2. Nielsen Norman Group's original **Ten Usability Heuristics** summary poster, under `03-nngroup-free-heuristic-posters/`: match real-world language, visibility and feedback, user control, consistent navigation, recognition rather than recall, prevention and recovery of errors, minimalist relevance, and contextual help.
3. Original **Laws of UX** offline pages `01-original-laws-of-ux/`: Jakob's Law (familiar conventions), Hick's Law (choice/decision load), cognitive load (cut jargon), proximity (group features and evidence), serial position (first and last information are memorable), and aesthetic–usability effect (clean visual perception is useful but not proof of effective task completion).
4. W3C WAI originals under `08-w3c-accessibility-and-patterns/`, including accessible forms and menu patterns. These are useful as a technical checklist; no unperformed WCAG certification is claimed.
5. Prior substantive marketing reading and limitations: `production/marketing-positioning-2026-11-19.md`; private extended Raspi marketing research at `/data/var/multiverse-marketing-research-20261119/`. Marketing depends on a buyer situation, comparator and evidence, not only big headline typography.

## Design decisions implemented

- First screen: name the situation where generic tooling may not fit, not whether AI can invoke tools. Shorter hero text on mobile and genuine, labeled project previews rather than invented screenshots.
- SWAAG: one clearly grouped **current baseline vs build-your-own system** section, with direct links to the competing product documentation; no invented uniqueness or benchmark victory.
- KMD: user problem is conflating identity, reports, contradictory and outdated evidence, not the already mainstream ability to search files. Honest DRT/DSPG research goal; a visibly experimental status and limited test below. Compare against ordinary agent document search explicitly, without claiming more accurate real-world answers.
- CapOv: compact secondary product proof with actual PyPI/GitHub links and install command. Do not imply the standalone tool is a game-changing replacement for existing static analysis or that PyPI downloads equal users.
- Keep five-site-section navigation consistent, separate publication categories, direct source links, concise captions/labels and real no-action limits. Test mobile 360/390, desktop/tablet, browser interactions, horizontal overflow, video playback and site generation reproducibility. No analytics or visitor tracking deployed.

## Unresolved evidence

No prospective buyer interviews or reliable comparative task benchmark have established the most attractive SWAAG/KMD positioning. The owner SWAAG project has been explicitly instructed to produce a real measured demo. For KnowMoreDiRT the next useful test is a controlled head-to-head on identical source collections (ambiguous people, contradictory events, quoted claims, dated changes, unsupported facts) against a current coding/document agent with equivalent available files/tools and a neutral evaluator. Record error, abstention, provenance and latency, including negative results. Do not claim experimental superiority or market share from self-written fixtures or hypothetical examples.
